🚀 開發階段拆解 (Phases)

Phase 1: 協作通訊底層建設 (CollabEngine & Yjs)

目標：建立穩定、低延遲且具備防衝突 (CRDT) 的資料同步管道。

  • 引入 Yjs 作為核心 CRDT 結構，取代單純的 JSON 快照覆蓋。
  • 實作 CollabEngine.js，負責接管 WebSocket 的連線生命週期與房間隔離。
  • 實作「加入房間/離開房間」的廣播機制，並接上先前開發的 PresenceManager。

Phase 2: 畫布物件增量同步 (Fabric.js 綁定)

目標：將 Yjs 的資料變更精準且雙向綁定到 Fabric.js 畫布物件上。

  • 攔截 Fabric.js 的修改/新增/刪除事件，將變更精準發布到 Yjs Array/Map 中。
  • 監聽 Yjs 的 observe 事件，自動更新畫布上其他使用者修改的物件，而不影響當前使用者的操作。

Phase 3: 多人游標與使用者識別 (Multiplayer Cursors)

目標：提供直觀的共同作業體驗，讓大家看到彼此「在哪裡」。

  • 實作 MultiplayerCursorOverlay.js：在 Fabric 畫布上層疊加獨立的游標渲染層。
  • 高頻廣播滑鼠座標，並根據 PresenceManager 提供的會員顏色渲染游標與名牌。
  • 實作平滑移動動畫 (LERP) 以降低網路傳輸帶來的視覺卡頓感。

Phase 4: 狀態鎖定與衝突防止 (Object Lease)

目標：避免兩人同時拖曳同一個物件造成資料抖動與覆蓋。

  • 當 User A 點擊選取某物件時，向網路發送「租約 (Lease)」請求。
  • 其他使用者的畫面上，該物件會顯示 鎖定框 (紅框或擁有者顏色的框)，且被設為無法選取 (`selectable: false`)。
  • 放開選取時，釋放該物件的租約。

📖 專有名詞說明

Yjs (CRDT)
Conflict-free Replicated Data Type。一種無衝突的資料結構，能確保在多個使用者同時離線編輯或網路延遲的情況下，大家最終看到的資料都會自動合併且保持一致，是現代共編軟體（如 Figma, Notion）的核心基石。
WebSocket / WebRTC
即時雙向通訊技術。相較於傳統的 HTTP 請求，能讓伺服器主動推播（廣播）資料給所有在房間內的使用者，實現「即時」看到對方游標與動作的效果。
Object Lease (物件租約)
為了解決物理衝突的機制。當某人點中畫布上的某個形狀時，他會暫時「租借」該物件的修改權（鎖定），此時其他人畫面上該物件會變色並禁止選取，直到原擁有者放開為止。
Presence (在線狀態)
紀錄與廣播當前在同一個協作房間內的成員名單與活躍狀態（包含他們被分配的顏色、顯示名稱、最後活動時間等），用於渲染頭像與游標名牌。
LERP (線性插值)
Linear Interpolation。為了避免游標因網路延遲而「瞬間移動」，透過數學算法補足兩點之間的移動軌跡，讓游標看起來是平滑滑動的。

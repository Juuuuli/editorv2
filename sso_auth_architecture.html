💡 關鍵解惑：系統 Key 是什麼？何時發放？怎麼發放？
1

Key 到底在「什麼時候發放」？「怎麼發放」？

發放時機：【各系統初次架設上線時 (只發一次)】

具體發放 3 步驟：
步驟 1： 管理員在「帳號 Admin」後台點選【新增模組 ➔ 系統 1、2、3、4】。
步驟 2： Admin 為每個系統自動產出一組「專屬 Key (密鑰)」。
步驟 3： 工程師把 Key 複製貼到該台電腦的設定檔（.env）裡。
➔ 各系統的電腦從此擁有專屬身分證！
2

既然各系統在不同電腦，為什麼每個系統都要 Key？

因為各系統電腦互相獨立，Admin 必須防止駭客冒充：

• 系統身分識別： 系統 2 要向 Admin 查 API 3 時，必須出示 系統 2 Key，Admin 才能確認「這真的是我認可的合法系統 2 主機」。
• 系統 4 (無人機器)： 沒有真人輸入帳密，系統 4 直接用它的 系統 4 Key 呼叫 Admin 執行自動備份。
3

超簡短總結：Key (系統鑰匙) vs Token (人員票券)

只要分清「給誰用的」就完全懂了：

• Key (系統身分證)： 發給「電腦 / 系統」。建置時發放一次，長效固定，放在伺服器內。
• Token (個人通行證)： 發給「登入的使用者」。每次輸入帳密時臨時產生，跟著瀏覽器跑，過期自動重發。

🏗️ EditorV2 系統總覽

EditorV2 是一套以瀏覽器為載體的多媒體畫布編輯器，支援 PDF 分頁編輯、無邊界圖片畫布、即時多人協作、AI 輔助工具等功能。以下是系統的全局鳥瞰。

系統啟動初始化流程

當瀏覽器載入 index.html 後，main.js 在 DOMContentLoaded 事件中依序實例化所有模組。以下是啟動順序。
document.addEventListener('DOMContentLoaded', () => {
    // 實例化全域 EventBus
    const eventBus = new EventBus();

    // 實例化 SPA 專案路由管理器
    const projectRouter = new ProjectRouter(eventBus);

    // 實例化繪圖核心引擎 CanvasEngine
    const canvas = new CanvasEngine('main-canvas', {
        width: 1280, height: 720
    }, eventBus);

    // 實例化即時協作模組 (Yjs + Firebase)
    const collabModule = new CollaborationModule(eventBus, authManager, projectRouter, canvas);

    // 實例化專案儲存引擎 (IndexedDB)
    const storageEngine = new ProjectStorageEngine(authManager);

    // 解析 URL 並執行路由跳轉
    projectRouter.init();
});

⚙️ 核心引擎

核心層的三大引擎 — CanvasEngine（畫布）、ProjectRouter（路由）、AIProviderAdapter（AI 抽象）— 是整個系統的基石。

CanvasEngine — Fabric.js 畫布引擎
包裝 fabric.js，提供 Artboard（畫板）、History（Undo/Redo）、Zoom/Pan 三大功能。所有畫布操作都透過它進行。
CJK 修正：CanvasEngine 開頭 patch 了 Fabric.js 的 enlargeSpaces 和 _renderChars 方法，修正中文字在 justify 對齊模式下無法正確分散排列的問題。這是因為 Fabric.js 原生只用空白字元分割，而中文沒有空白。

CanvasEngine 核心功能

功能說明關鍵方法
Artboard 畫板建立固定尺寸的白色矩形作為「紙張」，所有物件在其上編輯initArtboard()
History 歷史基於狀態快照的 Undo/Redo，每次修改存整個 canvas JSONundo() / redo() / saveState()
Zoom / Pan滑鼠滾輪縮放、空白鍵拖曳平移zoomIn() / zoomOut() / fitToScreen()

CJK Justify 修正程式碼

此 Patch 解決了 Fabric.js 原生無法處理 CJK 字元分散對齊的問題。
// CJK 修正：若沒有空白字元，則平均分配給所有字元（除最後一個）
numberOfSpaces = line.length - 1;
if (numberOfSpaces > 0) {
    diffSpace = (this.width - currentLineWidth) / numberOfSpaces;
    for (var j = 0, jlen = line.length; j <= jlen; j++) {
        charBound = this.__charBounds[i][j];
        charBound.left += accumulatedSpace;
        if (j < jlen - 1) {

            charBound.kernedWidth += diffSpace;
            accumulatedSpace += diffSpace;

init() {
    if (this.isInitialized || typeof window === 'undefined') return;

    // 初始化載入時解析當前網址
    const { projectId, roomId } = this.getQueryParams();
    this.currentProjectId = projectId;
    this.currentRoomId = roomId;

getActiveLlmModelName() {
    const isCustom = this.config.activeLlmType === 'custom';

        const activeEp = this.config.customEndpoints?.find(e => e.id === this.config.activeCustomId);

        return '未知內建模型';
    }
}

📡 EventBus 事件匯流排

EventBus 是整個系統的神經系統。所有模組之間不直接呼叫彼此的方法，而是透過 EventBus 發送與監聽事件來通訊，實現完全解耦。

為什麼用 Pub/Sub？因為模組之間如果直接互相 import，一旦要抽換或刪除某個模組，會牽一髮動全身。用 EventBus 後，每個模組只認識 EventBus，不認識其他模組。新增功能只要監聽對應事件即可，不用改任何既有程式碼。

EventBus 完整原始碼

極簡設計 — 只有 on（監聽）、off（取消監聽）、emit（發送）三個方法。
export default class EventBus {
    constructor() {
        this.listeners = {};   // { eventName: [callback1, callback2, ...] }
    }

    // 註冊事件監聽器
    on(event, callback) {
        if (!this.listeners[event]) {
            this.listeners[event] = [];
        }
        this.listeners[event].push(callback);
    }

    // 取消事件監聽器
    off(event, callback) {
        if (this.listeners[event]) {
            this.listeners[event] = this.listeners[event].filter(cb => cb !== callback);
        }
    }

    // 發送事件（通知所有監聽者）
    emit(event, data) {
        if (this.listeners[event]) {
            this.listeners[event].forEach(callback => callback(data));
        }
    }
}

模式切換核心邏輯

switchMode(newMode, force = false) {
    if (this.currentMode === newMode) return;
    
    // 有未儲存修改時，詢問使用者
    if (!force && this.isDirty) {
        const confirmSwitch = window.confirm(
            "目前畫布有未儲存的變更，切換工作區將清除畫布，是否繼續？"
        );
        if (!confirmSwitch) return;
    }

    this.currentMode = newMode;
    this.isDirty = false;
    
    this.updateUI(newMode);
    
    // 廣播事件，CanvasEngine 和 ThumbnailsPanel 會回應
    this.eventBus.emit('WORKSPACE:MODE_CHANGED', { mode: newMode });
}

IndexedDB 初始化

使用瀏覽器原生 IndexedDB API，建立 projects Object Store，以 id 為主鍵。
async init() {
    if (this.db) return this.db;

    return new Promise((resolve, reject) => {
        const request = indexedDB.open(this.dbName, this.dbVersion);

        request.onupgradeneeded = (event) => {
            const db = event.target.result;
            if (!db.objectStoreNames.contains(this.storeName)) {
                const store = db.createObjectStore(this.storeName, { keyPath: 'id' });
                store.createIndex('updatedAt', 'updatedAt', { unique: false });
                store.createIndex('type', 'type', { unique: false });
            }
        };

        request.onsuccess = (event) => {
            this.db = event.target.result;
            resolve(this.db);
        };
    });
}

👥 即時多人協作

協作系統是整個 EditorV2 最複雜的模組。基於 Yjs (CRDT) 實現衝突自動合併。

什麼是 CRDT？Conflict-free Replicated Data Type（無衝突複製資料型別）。多個使用者同時修改同一份資料時，CRDT 保證所有人最終收斂到一致的狀態，不需要集中式鎖定或衝突解決。Yjs 是最流行的 JavaScript CRDT 實現。

CollabEngine — 房間管理
負責 Yjs 房間的生命週期：建立 Y.Doc、連線 FirebaseProvider、管理 Awareness 狀態。

連線流程

connect(projectId, roomId) {
    if (this.projectId === projectId && this.provider) return; // 已連線

    this.disconnect();
    const roomName = `editorv2_yjs_${projectId}_${roomId}`;

    // 1. 建立 Y.Doc (CRDT 文件)
    this.ydoc = new Y.Doc();
    
    // 持久化 clientID 避免重新整理後產生「幽靈鼠標分身」
    let myClientId = sessionStorage.getItem('yjs_client_id');
    if (myClientId) {
        this.ydoc.clientID = parseInt(myClientId, 10);
    } else {
        sessionStorage.setItem('yjs_client_id', this.ydoc.clientID.toString());
    }

    // 2. 建立 Firebase Provider (負責把 Y.Doc 更新推送到 Firebase)
    this.provider = new FirebaseProvider(roomName, this.ydoc);
    this.awareness = this.provider.awareness;

    // 3. 初始化本地 Awareness 狀態 (游標位置、使用者名稱、顏色)
    const localUser = this.presenceManager.getLocalUser();
    this.awareness.setLocalStateField('user', localUser);
}
FirebaseProvider — Firebase ↔ Yjs 橋接
將 Yjs 的 binary update 編碼為 Base64 推送到 Firebase Realtime Database，反之從 Firebase 收到更新後 apply 到本地 Y.Doc。

YjsAdapter — Fabric ↔ Yjs 雙向綁定
這是協作系統最關鍵的橋接模組。它在 Fabric.js 事件與 Yjs 共享資料結構之間建立雙向同步。

雙向同步機制

方向觸發事件動作
Fabric → Yjsobject:added將物件 JSON 存入 yObjects Map
Fabric → Yjsobject:modified更新 yObjects 中對應物件
Fabric → Yjsobject:removed從 yObjects 中刪除物件
Yjs → FabricyObjects.observe()偵測變更，執行 canvas.add/modify/remove
頁面同步yPages.observe()同步多頁文件的頁面結構
迴圈防護：YjsAdapter 內部用 flag 區分「本地操作」和「遠端同步」，避免 Fabric→Yjs→Fabric 的無限迴圈。當收到遠端更新並 apply 到畫布時，會暫時忽略 Fabric 的事件。
PresenceManager & MultiplayerCursorOverlay
PresenceManager 管理使用者在線狀態（名稱、顏色）。MultiplayerCursorOverlay 在畫布上方渲染其他使用者的即時游標位置。

游標渲染機制

CursorOverlay 是一個覆蓋在 Canvas 上方的 DOM 層（不是畫在 Canvas 裡面），避免干擾畫布渲染。每個遠端使用者的游標用 <div> 呈現，包含色彩圓點和使用者名稱標籤。

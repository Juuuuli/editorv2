現有架構釐清與未來擴充提案

1. 現有系統 API/AI 服務盤點

在討論擴充之前，我們必須先釐清「哪些是 AI 模型？哪些只是一般雲端服務？」
目前我們的編輯器主要使用了 三種截然不同 的服務，它們在未來的擴充方式也完全不同：

生成式 AI 模型 (LLM/VLM)

目前串接：OpenAI Vision API (GPT-4o-mini)

負責功能：框選畫布文字區域，辨識複雜版面、文字擷取與多國語言 (OCR 智慧辨識)。

擴充與技術替換方案

可從 OpenAI 雲端服務替換為純前端邊緣運算的 Tesseract.js，或內網自建的 Ollama (Vision) 模型，實現完全斷網辨識。

專業影像 AI 服務

目前串接：Clipdrop API (Inpainting & Remove-BG)

負責功能：透過生成式 AI 無縫去背與填補抹除物件後的背景 (去背與塗抹修補)。

擴充與技術替換方案

目前使用雲端生成，未來可串接私有部署的 Stable Diffusion 伺服器，或開源的 Lama Cleaner，確保修改圖片不外流。

傳統 SaaS 雲端服務

目前串接：ConvertAPI

負責功能：將企業常見的 PPT 簡報雲端轉換為標準 PDF，以利匯入畫布成為多頁面專案 (簡報解析)。

擴充與技術替換方案

除了依賴目前的 ConvertAPI 外，系統設計相容於自架的 LibreOffice (Gotenberg) 伺服器，可隨時切換為 100% 內網離線轉檔架構。

2. 我們的系統該做到什麼程度？

基於上述分析，我建議將「系統金鑰保險箱」拆分為兩大類別頁籤：

  • A. 語言與視覺模型 (核心大腦)
    這裡實作您主管提到的「動態切換模型」功能。 提供 內建主流 (OpenAI/Anthropic) 以及 自訂 OpenAI 相容端點 兩種模式。世界上絕大多數開源模型 (含 vLLM, Ollama) 都支援 OpenAI 的 API 格式，因此我們只要實作一套「自訂 Base URL + Key」的介面，就能吃下幾乎所有的開源模型，無須為每個模型客製化開發。
  • B. 專業外掛服務 (去背 / 轉檔)
    這裡保留原本的 Clipdrop (去背修圖) 與 ConvertAPI (PPT 轉檔) 輸入框。因為這類服務是功能特化型的，API 格式各不相同，直接讓使用者填入官方 Key 是最務實的做法，不需要做複雜的「模型選擇」。

# 🎨 多媒體畫布編輯器 V2 - 全系統風格指令總綱 V2 (Themes Master Directive V2)

> **⚠️ 系統級約束聲明**
> 這是一份給予 Agent 與開發者的「決定性提示詞 (Deterministic Prompt)」。
> 本文件所定義的架構、限制與禁止事項，高於任何單一主題的美學要求。任何主題 (Theme) 的實作**必須**遵循此總綱的 UX 互動邏輯與 HTML 骨架規範。

---

## 1. 模組架構與切換機制 (維持原有邏輯)

本系統採用 **CSS Scope 與 Data-Attribute 動態切換架構**：
透過更新 `document.documentElement` 的 `data-theme` 屬性，配合各主題 `.css` 檔內的覆寫機制達成無重繪 (No-Repaint) 切換。

---

## 2. 嚴格 UX 互動與體驗規範 (UX Constraint Blueprints)

除了顏色與陰影，不同主題必須具備**完全相同**的互動邏輯與 HTML 結構：

### 2.1 層級式操作與抽屜 (List & Drawer Pattern)
- **禁止攤平**：絕不可將複雜的表單、資料細節與列表擠在同一個頁面上。
- **抽屜優先**：點擊列表項目後，**必須**從畫面右側滑出抽屜 (Drawer) 顯示細節與設定。
- **彈窗限制**：全螢幕或置中彈窗 (Modal) **僅限用於**「單次新增行為」或「破壞性確認 (如刪除)」。

### 2.2 防呆與取捨說明框 (Note Component Blueprint)
遇到需解釋系統限制的場景，**必須**套用此 Note 元件骨架，而非單純寫純文字：
```html
<!-- HTML 骨架：全站通用，各主題僅覆寫顏色 -->
<div class="theme-note-box">
  <div class="theme-note-bar"></div>
  <div class="theme-note-content">
    <strong>取捨標題：</strong>講因果，不只講規則。
  </div>
</div>
```

---

## 3. 全局語意色約定 (Global Semantic Rules)

各主題可自定義具體的色碼，但必須遵守以下「語意約束」：
- 🟢 **Success (成功/完成)**：例如綠色，絕對不可用於一般的「確認/送出」按鈕，只能用來表示狀態。
- ⚪/⚫ **Primary (主要動作)**：每頁**最多一個**主要按鈕，必須採用該主題下最高對比的實色（例如黑底白字或白底黑字），不可使用鮮豔語意色。
- 🔴 **Danger (危險/刪除)**：必須搭配防呆確認 Modal，按鈕需用明顯的警告色與警示 Icon。

---

## 4. 嚴格禁止事項清單 (Anti-Patterns / What NOT to do)

未來開發時，絕對禁止以下行為：
1. **🚫 禁止寫死 Inline Style**：`style="..."` 絕對禁止出現在正式元件中，所有樣式必須進 CSS 變數或 class。
2. **🚫 禁止濫用 Tailwind 預設色碼**：禁止直接使用 `bg-blue-500` 等，必須使用各主題定義好的 `var(--bg-panel)` 或對應的語意 Class。
3. **🚫 禁止卡片與按鈕產生立體陰影**：除了 Modal、Drawer 或特定復古印章按鈕外，一般內容區塊**嚴格禁用 `box-shadow`**，一律以 0.5px 的 `border` 來區分層級。

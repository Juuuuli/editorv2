產品釋出與 API 授權策略分析

探討如何將編輯器提供給外部使用者，以及安全的 API 金鑰管理方式

一、版本釋出方式 (Deployment)

1. 純前端網頁 (GitHub Pages)

您目前使用的方式。使用者透過瀏覽器即可開啟，無須安裝。

  • 優點： 免費、傳播速度最快。
  • 缺點： 無法安全隱藏您的 API Key，除非讓使用者自己輸入。且內網伺服器 (如 vLLM) 外部無法連線。

2. 桌面應用程式 (Electron/Tauri)

將網頁打包成 Windows (.exe) 或 Mac (.dmg) 的獨立軟體。

  • 優點： 感覺更專業、可離線存檔、能更安全地把 API Key 寫死在軟體底層。
  • 缺點： 使用者需要下載安裝，且有軟體憑證簽章問題。

3. 企業私有部署 (Docker)

將編輯器與後端打包成容器，交給其他公司的 IT 部門架設。

  • 優點： 最適合企業賣斷或授權，能解決內網 (如 vLLM) 連線問題。
  • 缺點： 對一般個人使用者門檻極高。

二、讓使用者自訂 API Key 的做法 (BYOK)

如果我們維持在 GitHub Pages，絕對不能把您的金鑰放在程式碼裡。我們必須採用 BYOK (Bring Your Own Key) 策略：

做法：建立「系統設定」面板

在網頁右上角新增一個「設定」按鈕。當使用者第一次使用「去背」或「PDF匯出」時，彈出視窗要求他們輸入自己的 API Key。

// 1. 儲存使用者的 Key 到他們的瀏覽器 (LocalStorage)
localStorage.setItem('USER_CLIPDROP_KEY', '使用者輸入的字串');

// 2. 呼叫 API 時，改抓 LocalStorage 的 Key
const apiKey = localStorage.getItem('USER_CLIPDROP_KEY');

優勢

您完全不需要付擔伺服器與 API 費用。使用者的金鑰只存在他們自己的電腦裡，非常安全。

補充說明：CORS 問題

有些 API (如 OpenAI) 會阻擋從「前端網頁」直接呼叫 (CORS 限制)。不過 Clipdrop 與 ConvertAPI 目前在設計上是允許直接呼叫的。如果未來遇到阻擋，使用者可能還是得透過 Proxy 才能打通 API。

三、補充建議：如果想把這當作一個商業產品？

如果您未來希望開放給大眾使用，但不想要使用者「覺得麻煩去申請一堆 API Key」，您可以考慮 BaaS (Backend as a Service) 架構：

  • 架設一個輕量中繼後端 (Vercel / Cloudflare Workers)

    網頁不直接呼叫 Clipdrop，而是呼叫您架設的免費後端。API Key 藏在您的後端裡。這樣使用者打開網頁就能直接用。

  • 加入會員登入機制 (Firebase Auth)

    為了避免您的 API 額度被惡意刷爆，中繼後端可以檢查使用者是否登入，並限制每個帳號每天只能去背 10 次。

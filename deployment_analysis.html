系統部署與架構策略報告

針對「內部測試」與「正式上線」的兩種部署方案解析

當前系統架構

目前系統為 100% 純前端架構 (Vite + Fabric.js)，所有運算都在瀏覽器內完成，無需後端資料庫，理論上可以直接託管於任何靜態網頁伺服器。

核心資安挑戰

我們使用了 Clipdrop (去背) 與 ConvertAPI (PPT 轉檔) 兩個付費 API。如果直接發布前端程式碼，金鑰將以純文字暴露，任何人都能盜用金鑰並刷爆您的額度。

執行中

方案 C：內部測試直上 (免 Server 架構)

適用情境：提供給主管或內部少數人員進行功能預覽、體驗測試。

1. 全螢幕密碼大門 (Password Gate)

在進入系統前，我們已加入了一道全螢幕的密碼驗證畫面 (目前設定為 DEMO2026)。這能阻擋 99% 的搜尋引擎爬蟲與路人，避免他們誤觸按鈕消耗 API 額度。

2. 隱蔽的靜態網址部署

將專案編譯打包後 (dist 資料夾)，直接丟上 Netlify Drop 等靜態託管平台。系統會隨機產生一組亂碼網址，只要不對外公開，外人幾乎不可能找到。

3. 第三方平台額度控管 (最後防線)

請務必前往 Clipdrop 與 ConvertAPI 的管理後台，設定帳單消費上限 (Billing Limits) (例如設定 5 美金)。這樣即使密碼遭到破解，也能確保損失在絕對可控範圍內。

方案 A：正式對外上線 (中介 Server 隱藏金鑰)

適用情境：專案正式對公眾開放，需要 100% 確保 API 金鑰安全且不可見。

我們不需要去租用昂貴的雲端主機 (如 AWS EC2) 或是寫一整套龐大的後端，只需利用 Vercel Serverless Functions 來當作「傳聲筒 (Proxy)」，預計 1~2 小時即可改建完成。

1

建立後端 API (Serverless 函式)

在專案根目錄新增一個 api/ 資料夾，並撰寫 Node.js 程式碼 (例如 api/convert-ppt.js)。這段程式碼將會在 Vercel 的雲端獨立運行，負責幫前端拿著金鑰去向 ConvertAPI 溝通。

2

將金鑰從前端拔除 (變更變數名稱)

將原本寫在 .env 裡的 VITE_CONVERTAPI_SECRET 改名為 CONVERTAPI_SECRET。在 Vite 的架構中，只要不加 VITE_ 前綴，金鑰就絕對不會被打包進前端程式碼中，確保金鑰只活在後端。

3

修改前端的呼叫對象

原本前端是直接呼叫：fetch('https://v2.convertapi.com/...')
改為呼叫自己的後端：fetch('/api/convert-ppt')
前端只需要負責交出檔案，完全不用知道金鑰是什麼。

4

一鍵部署至 Vercel

將專案與 GitHub 連動後部署到 Vercel 平台。在 Vercel 後台將 CONVERTAPI_SECRET 填入環境變數設定中。Vercel 會自動為您架設好靜態前端，並同時把 api/ 資料夾變為高效能的中介 Server。

方案 B：使用者自帶金鑰 (BYOK 模式)

如果您完全不想碰觸任何後端與 Vercel，可以在系統內實作一個「設定頁面」。強制每個使用者註冊自己的 Clipdrop 與 ConvertAPI 帳號，並將他們的金鑰儲存在自己的瀏覽器中。這樣能做到 100% 無伺服器且零資安風險，但會嚴重損害使用者的體驗，不適合作為對外營利的標準商業模式。

# 系統標準規範 (v0)

> 本規範確立「多媒體畫布編輯器V2」的全域開發標準與設計模式。

## 1. 核心開發準則
1. **絕對功能隔離 (Feature-based Isolation)**：
   - 所有的功能模組（四大面板、各項子工具）必須強制拆分為獨立的資料夾與獨立檔案。
   - 嚴禁單一檔案 (例如 `MainEditor.js` 或 `Tools.js`) 存放混合邏輯。若單一檔案超過 300 行，即代表需要進一步拆分。
2. **事件驅動架構 (Event-Driven)**：
   - 跨模組溝通（例如「左側工具」去改變「中央畫布」的狀態，或影響「右側縮圖」）一律透過 EventBus 或全域狀態管理 (State Manager)。
   - 絕對禁止模組之間互相直接 `import` 呼叫彼此的類別與函式，以防止高耦合與「義大利麵條程式碼」。
3. **UI 與邏輯分離**：
   - UI 介面層 (HTML / TailwindCSS) 僅負責渲染。
   - 業務與圖形邏輯層 (Canvas 操作、Fabric.js 綁定、API 呼叫) 封裝於單獨的 JavaScript Class/Module 中。

## 2. 嚴格目錄結構
- `/core`：存放系統最底層核心邏輯，如 `CanvasEngine.js` (負責繪圖引擎與碰撞偵測)、`HistoryManager.js` (Undo/Redo)、`StorageManager.js`。
- `/features`：所有可見面板與獨立功能模組的存放區。各模組資料夾內必須具備專屬的 `[模組名稱]_規則v0.md`。
  - `/features/tools/basic`：選取、平移、畫筆等。
  - `/features/tools/smart`：一鍵去背、OCR 等需依賴 API 的工具。
  - `/features/tools/objects`：文字、QR Code 等新物件。
  - `/features/floating_tools`：畫布右下角的全螢幕、留言等快捷工具。
- `/shared`：存放 EventBus、自訂 Hook 或共用的 API 通訊模組 (`APIClient.js`)。

## 3. 命名與編碼規範
- **檔案/類別名稱**：採用大駝峰命名 (PascalCase)，如 `BrushTool.js`, `CanvasEngine.js`。
- **變數/函式名稱**：採用小駝峰命名 (camelCase)，如 `initCanvas`, `currentActiveLayer`。
- **CSS Class 命名**：依循 TailwindCSS 規範。自定義樣式 (如手繪風格的 `.sketch-btn`) 必須採用烤肉串命名法 (kebab-case) 並統一放於入口 CSS 中。
- **環境變數**：API Key 等敏感資訊強制存放於 `.env` 中，不可 hardcode 在程式碼內。

## 4. 防呆機制與邊界處理
- **前置狀態檢查**：所有「智慧去背與修補」模組在觸發前，必須檢查 `Workspace.hasImportedFile`，若無檔案則直接 return 避免噴錯。
- **邊界物理限制 (Bounding Box)**：任何畫布物件 (包含群組化後的物件) 的 `object:moving` 事件，都必須由 `CanvasEngine` 統一過濾座標。若 X 或 Y 超出白色畫布長寬範圍，必須強制設定回邊界值，實現「撞牆」效果。
- **比例鎖定**：當監聽到 `EVENT:FILE_IMPORTED` 時，UI 層必須立即禁用(Disable)頂部的畫布比例切換按鈕。

# 系統標準規範 (v2)

> **版本狀態**：正式發布  
> **適用版本**：`v1.5.0` ~ `v2.0.0` (由目前穩定版 `v1.4.1` 演進)  
> **文件目的**：確立「多媒體畫布編輯器 V2」的全域開發標準、SPA 路由架構、多人協作前置通訊準則與編碼規範。所有參與開發之工程師與 AI Agent 均須嚴格遵守。

---

## 1. 核心架構準則

### 1.1 絕對功能隔離 (Feature-based Isolation)
* 所有的功能模組（儀表板、主題管理、帳號認證、協作共編、智慧輔助線、四大面板、各項子工具）必須強制拆分為獨立的資料夾與檔案。
* 嚴禁在單一檔案內存放混合邏輯。若單一檔案超過 300 行，即代表職責過多，必須進行模組化拆分。
* **模組自包含文件 (Self-Documenting Modules)**：每個 `src/features/[feature_name]/` 目錄內必須包含專屬的 `README.md`，清楚記載該模組之對外暴露方法、EventBus 監聽/發送之事件清單與 UI 相依性。

### 1.2 事件驅動通訊 (Event-Driven Architecture)
* 跨模組溝通（例如：路由切換專案 -> 畫布載入資料、選單點擊分享 -> 開啟協作彈窗）一律透過 `shared/EventBus.js` 進行廣播與監聽。
* 嚴禁模組之間直接以實例 (Instance) 互相強耦合呼叫，確保各模組可獨立抽換與單元測試。

### 1.3 UI 樣式與狀態分離 (Tokens & State Separation)
* **色彩與樣式**：所有外觀樣式必須依循 Design Tokens (CSS Variables) 設計，嚴禁在元件內部將顏色 hardcode 寫死，以確保「顏色模板與主題切換」功能之完整套用。
* **持久化分離**：儲存操作統一經由 `ProjectStorageEngine` 封裝，UI 元件不直接呼叫底層 IndexedDB 或 localStorage。

## 2. 升級模組專屬規範

### 2.1 專案儲存規範 (Storage Protocol)
* **專案資料結構**：每一個專案必須包含標準元資料（`id`, `title`, `coverImage`, `createdAt`, `updatedAt`, `creator`, `canvasData`）。
* **Auto-Save 規範**：監聽 `CANVAS:DIRTY` 事件時，必須實施防抖 (Debounce 800ms) 寫入 IndexedDB，嚴禁頻繁無節制地進行磁碟 I/O。

### 2.2 主題與視覺規範 (Theme & UX Guidelines)
* **手繪風格優先**：系統預設主題必須保持「經典手繪風 (Light Sketch)」之暖色底與雙線邊框（`.sketch`、`.sketch-btn`）。
* **選取框樣式**：選取物件時，必須維持客製化「紅色虛線選取框」。
* **平移行為**：平移畫布必須帶動整體 Viewport（包含白色工作底板一起移動），不可僅移動內部物件。
* **智慧輔助線**：採用 Canva 風格 1px 極細向量準線，滑鼠放開或物件遠離磁吸範圍時必須在 0ms 內自動清理上層 Canvas 像素。

### 2.3 帳號與安全規範 (Auth & API Vault Protocol)
* **公用管理者帳密**：配置一組公用主帳密作為系統全功能通行證，預留標準 RBAC (Admin, Editor, Viewer) 權限模型。
* **模組化隔離 (`ApiVaultManager.js`)**：保險箱 UI 與金鑰管理由 `src/features/vault/ApiVaultManager.js` 獨立封裝，不與登入認證邏輯混淆。
* **3 大服務分類標準**：
  1. 🧠 **AI 核心模型 (LLM)**：支援主流雲端 (OpenAI/Anthropic) 與 OpenAI 相容自訂端點 (vLLM/Ollama)。
  2. 🖼️ **影像處理服務**：支援 Clipdrop、Photoroom、Remove.bg、Stable Diffusion。
  3. 📊 **簡報轉檔解析**：支援 ConvertAPI、CloudConvert、Gotenberg (Docker)。
* **API 金鑰安全與持久化**：所有自訂金鑰與端點統一加密/結構化存於瀏覽器 `localStorage`（Key: `EDITOR_V2_VAULT_CONFIG`），嚴禁明文發送至公開儲存庫。
* **多主題語意化樣式**：彈窗樣式強制使用 `settings-modal.css` 語意化類別，確保 4 款系統主題皆可正常呈現。

### 2.4 SPA 前端專案路由規範 (SPA Project Routing Protocol) —— 【v1.5.0 新增】
* **網址標準**：
  * 首頁儀表板：`/editorv2/`
  * 開啟特定專案：`/editorv2/?project=[PROJECT_ID]`
  * 協作房間網址：`/editorv2/?project=[PROJECT_ID]&room=[ROOM_ID]`
* **History API 操作原則**：
  * 專案與儀表板之切換必須調用 `window.history.pushState`，嚴禁引發整個瀏覽器頁面重新整理 (Full Page Reload)。
  * 必須監聽 `window.onpopstate` 事件，使瀏覽器「上一頁/下一頁」能夠原生倒退/前進於專案與儀表板之間。
* **Deep Linking 容錯機制**：若 URL 帶有 `project` 參數但本地或雲端查無該專案，必須優雅降級回儀表板，並彈出手繪風 Toast 提示「查無此專案」。

### 2.5 專案協作與 Presence 規範 (Collaboration & Presence Protocol) —— 【v1.5.0 新增】
* **進入點收納**：專案協作與分享入口必須收納於右上角使用者選單中，保持介面簡潔。
* **身分與配色分配 (`PresenceManager`)**：
  * 每位協作者進入專案時，自動從預設調色盤中分配專屬顏色（Cyan, Pink, Violet, Emerald, Amber 等）。
  * 協作者名稱優先採用 `AuthManager` 當前登入的使用者名稱，未登入者自動給予訪客標籤。
* **本機雙分頁測試通道 (`CollabChannel`)**：
  * 採用原生 `BroadcastChannel` 進行跨分頁通訊，支援在無後端伺服器環境下使用「一般視窗 + 無痕視窗」即時驗證 Presence 狀態同步。
* **權限角色模型**：
  * ✏️ **Editor (編輯者)**：擁有完整的畫布修改與同步權限。
  * 👁️ **Viewer (檢視者)**：進入唯讀模式，鎖定畫布所有互動，僅供展示與觀看。

### 2.6 版本控制規範 (Semantic Versioning Automation)
* **修復 Bug (Fix)**：自動將 `package.json` 的 Patch 版號 +1（例如 `1.4.0` -> `1.4.1`）。
* **新增功能 (Feature)**：自動將 `package.json` 的 Minor 版號 +1（例如 `1.4.1` -> `1.5.0`）。
* **重大架構突破 (Major)**：全功能即時共編上線升級為 `2.0.0`。
* **每次 Commit / Push**：必須確實包含版號與相關文檔的同步變更。

## 3. 命名與編碼慣例

* **Class 類別與檔名**：大駝峰 PascalCase（如 `ProjectRouter.js`, `ShareModal.js`, `PresenceManager.js`）。
* **變數與函式**：小駝峰 camelCase（如 `navigateToProject`, `copyShareLink`）。
* **自訂 CSS Class**：烤肉串 kebab-case（如 `.collab-share-modal`, `.presence-badge`）。
* **EventBus 事件命名空間**：
  * 路由事件：`ROUTER:PROJECT_CHANGED`, `ROUTER:NAVIGATE_DASHBOARD`
  * 協作事件：`COLLAB:OPEN_SHARE_MODAL`, `COLLAB:ROOM_JOINED`, `COLLAB:PRESENCE_UPDATE`
  * 保險箱事件：`VAULT:OPEN_MODAL`, `VAULT:CONFIG_UPDATED`
  * 畫布事件：`CANVAS:DIRTY`, `CANVAS:SELECTION_CHANGED`

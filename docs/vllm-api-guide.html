vLLM API 串接指南

模型 Nemotron-3-Nano-Omni-30B（OpenAI 相容 API）　·　DGX Spark @ 10.1.1.103　·　2026-06-17
vLLM 本身就是 OpenAI 相容 API。你的後端不需要任何特製 client，直接用 OpenAI SDK 或 HTTP 呼叫即可，只要把 base_url 和 api_key 改掉。

2串接前必讀（重要特性）

① 這是「推理模型」，輸出分兩段：先 reasoning（思考），後 content（答案）。
max_tokens 一定要設大（建議 ≥ 1024）。若設太小，token 會全被思考用光，content 變成 null／空字串。（實測 max_tokens=80 時 content 確實為 null。）
② 思考欄位叫 reasoning（不是 OpenAI 慣例的 reasoning_content）。
  • 非串流：答案在 choices[0].message.content，思考在 choices[0].message.reasoning。
  • 串流：delta 會先收到一連串 delta.reasoning，再收到 delta.content —— 後端兩個都要處理。
③ 多模態：每個請求每種模態（image / audio / video）最多 1 個。

3curl 範例

3.1 健康檢查 / 列出模型

curl http://10.1.1.103:11435/health

curl http://10.1.1.103:11435/v1/models \
  -H "Authorization: Bearer token-123qwe"

3.2 基本對話（非串流）

curl http://10.1.1.103:11435/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer token-123qwe" \
  -d '{
    "model": "nemotron-omni",
    "messages": [
      {"role": "system", "content": "你是一個簡潔的繁體中文助理。"},
      {"role": "user", "content": "用一句話解釋什麼是 RAG"}
    ],
    "max_tokens": 1024,
    "temperature": 0.3
  }'
答案在 .choices[0].message.content；思考過程在 .choices[0].message.reasoning。

3.3 串流（SSE，逐字輸出）

curl -N http://10.1.1.103:11435/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer token-123qwe" \
  -d '{
    "model": "nemotron-omni",
    "messages": [{"role": "user", "content": "寫一首關於春天的短詩"}],
    "max_tokens": 1024,
    "stream": true,
    "stream_options": {"include_usage": true}
  }'
每行是 data: {...}；思考 token 在 delta.reasoning，答案 token 在 delta.content，結尾為 data: [DONE]。首字延遲約 0.4 秒。

3.4 多模態（圖片）

curl http://10.1.1.103:11435/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer token-123qwe" \
  -d '{
    "model": "nemotron-omni",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "這張圖是什麼？"},
        {"type": "image_url", "image_url": {"url": "https://example.com/cat.jpg"}}
      ]
    }],
    "max_tokens": 1024
  }'
也支援 base64："url": "data:image/jpeg;base64,<...>"。每請求圖/音/影各限 1 個。

3.5 工具呼叫（function calling）

curl http://10.1.1.103:11435/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer token-123qwe" \
  -d '{
    "model": "nemotron-omni",
    "messages": [{"role": "user", "content": "台北現在天氣如何？"}],
    "tools": [{
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "查詢指定城市的天氣",
        "parameters": {
          "type": "object",
          "properties": {"city": {"type": "string", "description": "城市名稱"}},
          "required": ["city"]
        }
      }
    }],
    "tool_choice": "auto",
    "max_tokens": 1024
  }'
模型要呼叫工具時，結果在 .choices[0].message.tool_calls。

4OpenAI SDK 串接

Python

from openai import OpenAI

client = OpenAI(
    base_url="http://10.1.1.103:11435/v1",
    api_key="token-123qwe",
)

resp = client.chat.completions.create(
    model="nemotron-omni",
    messages=[{"role": "user", "content": "你好，請自我介紹"}],
    max_tokens=1024,          # 記得設大，否則答案被思考吃光
    temperature=0.3,
)
msg = resp.choices[0].message
print("思考：", getattr(msg, "reasoning", None))   # 推理過程
print("答案：", msg.content)                        # 最終回答

Node.js（openai 套件）

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "http://10.1.1.103:11435/v1",
  apiKey: "token-123qwe",
});

const r = await client.chat.completions.create({
  model: "nemotron-omni",
  messages: [{ role: "user", content: "你好" }],
  max_tokens: 1024,
});
console.log(r.choices[0].message.content);

GET /v1/models列出模型

POST /v1/completions文字補全（傳統 prompt 模式）
POST /tokenize · /detokenize計算 / 還原 token

GET /docs互動式 API 文件（Swagger，可線上試打）
互動文件可直接瀏覽：http://10.1.1.103:11435/docs

6安全與注意事項

  • 無 TLS（http，非 https）：目前純內網 http，API key 為明文傳輸。僅限信任的內網使用；若要對外，需在前面加反向代理（nginx / caddy）做 TLS。
  • 併發：同時最多 50 路；50 人同時生成時每人約 8 tok/s（一段 256 字約 32 秒）。建議後端優先用串流，首字僅約 0.4 秒，體感較佳。
  • 逾時設定：長回答請把 client timeout 設足夠（建議 ≥ 120 秒）。
  • max_tokens：因為是推理模型，務必設大（≥ 1024），否則 content 可能為空。

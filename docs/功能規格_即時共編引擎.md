# 功能規格：即時共編引擎 (v2.0.0)

本文件定義 Sprint 5 中「即時多人協作共編引擎」的系統規格與運作流程。

## 1. Yjs 資料結構對應 (Yjs Data Model)
為了將 Fabric.js 的畫布結構 (Pages -> Objects) 對應到 Yjs 的 CRDT 結構，我們定義以下 Yjs 架構：
- `Y.Doc`：代表單一專案。
- `Y.Map('project_metadata')`：儲存專案名稱、寬高比例、背景色等全域設定。
- `Y.Array('pages')`：代表簡報的頁面陣列。
- 每一個 Page 對應一個 `Y.Map`，內含 `id`, `thumbnail`，以及一個 `Y.Array('objects')`。
- `Y.Array('objects')` 內部存放每一個 Fabric Object 的 JSON 表示 (作為 `Y.Map` 存放屬性)。

## 2. WebRTC 連線與 Signaling
- 繼續使用 `peerjs` 進行 P2P 連線。
- Yjs 支援 `y-webrtc` 提供去中心化的 P2P 廣播，我們可結合 `y-webrtc` 來讓各端點同步 Yjs 的資料。
- 房主 (Host) 創建專案並產生 `roomId`，訪客 (Guest) 透過 URL 參數帶入 `roomId` 進行 `y-webrtc` 房間連接。

## 3. 多人動態游標 (Multiplayer Cursors)
- 透過 WebRTC 或 `CollabChannel.js` 高頻率 (例如每 50ms) 發送游標座標 `[x, y]`。
- 接收端將座標推入緩衝區，使用 LERP (線性插值) 算法平滑移動 DOM 元素游標。
- 游標的樣式與顏色由 `PresenceManager.js` 動態指派。

## 4. 物件租約與鎖定 (Object Lease)
- Yjs 提供 `Y.Awareness` (透過 `y-webrtc` 的 awareness 實作)。
- 當 User A 的畫布觸發 `mouse:down` 選中 `object_id_1` 時，更新自身的 Awareness 狀態 `{"selection": ["object_id_1"]}`。
- 其他 User 收到 Awareness 更新後，將 `object_id_1` 的邊框渲染為 User A 的顏色，並將其 `selectable` 設為 `false`。
- 當 User A 觸發 `selection:cleared` 時，清除 Awareness 中的 selection。

## 5. Fabric.js 與 Yjs 的雙向綁定 (YjsAdapter)
- **Local to Remote**：監聽 Fabric 畫布的 `object:modified`, `object:added`, `object:removed`。觸發時，尋找對應的 `Y.Map` 節點進行 `.set()` 或從 `Y.Array` 中 `.insert()` / `.delete()`。
- **Remote to Local**：監聽 Yjs 陣列與 Map 的 `observeDeep`。當接收到來自網路的變更且非本地操作時，呼叫 Fabric.js 的 API 去更新指定物件 (如 `obj.set(changes)`)，並呼叫 `canvas.renderAll()`。

# 系統標準規範 (v1)

> 本規範確立「多媒體畫布編輯器 V2」的全域開發標準、架構模式與編碼準則。所有參與開發之工程師與 AI Agent 均須嚴格遵守。

---

## 1. 核心架構準則

### 1.1 絕對功能隔離 (Feature-based Isolation)
* 所有的功能模組（儀表板、主題管理、帳號認證、協作共編、四大面板、各項子工具）必須強制拆分為獨立的資料夾與檔案。
* 嚴禁在單一檔案內存放混合邏輯。若單一檔案超過 300 行，即代表職責過多，必須進行模組化拆分。
* 各模組資料夾內必須具備專屬的規則或規格說明檔。

### 1.2 事件驅動通訊 (Event-Driven Architecture)
* 跨模組溝通（例如：儀表板開啟專案 -> 畫布載入資料、屬性面板修改 -> 畫布物件更新）一律透過 `shared/EventBus.js` 進行廣播與監聽。
* 嚴禁模組之間直接以實例 (Instance) 互相強耦合呼叫，確保各模組可獨立抽換與測試。

### 1.3 UI 樣式與狀態分離 (Tokens & State Separation)
* **色彩與樣式**：所有外觀樣式必須依循 Design Tokens (CSS Variables) 設計，嚴禁在元件內部將顏色 hardcode 寫死，以確保「顏色模板與主題切換」功能之完整套用。
* **持久化分離**：儲存操作統一經由 `ProjectStorageEngine` 封裝，UI 元件不直接呼叫底層 IndexedDB 或 localStorage。

---

## 2. 升級模組專屬規範

### 2.1 專案儲存規範 (Storage Protocol)
* **專案資料結構**：每一個專案必須包含標準元資料（`id`, `title`, `coverImage`, `createdAt`, `updatedAt`, `creator`, `canvasData`）。
* **Auto-Save 規範**：監聽 `CANVAS:DIRTY` 事件時，必須實施防抖 (Debounce 800ms) 寫入 IndexedDB，嚴禁頻繁無節制地進行磁碟 I/O。

### 2.2 主題與視覺規範 (Theme & UX Guidelines)
* **手繪風格優先**：系統預設主題必須保持「經典手繪風 (Light Sketch)」之暖色底與雙線邊框。
* **選取框樣式**：選取物件時，必須維持客製化「紅色虛線選取框」。
* **平移行為**：平移畫布必須帶動整體 Viewport（包含白色工作底板一起移動），不可僅移動內部物件。

### 2.3 帳號與安全規範 (Auth & API Vault)
* **公用管理者帳密**：目前設定一組公用主帳密作為系統全功能通行證。
* **API 金鑰安全**：使用者或管理者自訂之 API 金鑰一律存於使用者本地端（`localStorage` 加密或 Vault），嚴禁明文推播至公開儲存庫。

### 2.4 版本控制規範 (Semantic Versioning Automation)
* **修復 Bug (Fix)**：自動將 `package.json` 的 Patch 版號 +1（例如 `1.1.2` -> `1.1.3`）。
* **新增功能 (Feature)**：自動將 `package.json` 的 Minor 版號 +1（例如 `1.1.3` -> `1.2.0`）。
* **每次 Commit / Push**：必須確實包含版號與相關文檔的同步變更。

---

## 3. 命名與編碼慣例
* **Class 類別與檔名**：大駝峰 PascalCase（如 `ThemeManager.js`, `ProjectStorageEngine.js`）。
* **變數與函式**：小駝峰 camelCase（如 `switchTheme`, `saveCurrentProject`）。
* **自訂 CSS Class**：烤肉串 kebab-case（如 `.sketch-btn`, `.dark-theme`）。
* **常數與事件名稱**：全大寫蛇形 UPPER_SNAKE_CASE（如 `EVENT:PROJECT_LOADED`, `CANVAS:DIRTY`）。
